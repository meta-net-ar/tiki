# Tiki services (AJAX/REST controllers)

The modern way to expose data/behaviour to JS and third parties. Preferred over
legacy `ajaxlib`/`registerTemplate`. Paths below are relative to the Tiki
source-tree root; the cited files are real — open and copy from them.

## The three pieces (all required)

1. **Controller** — `lib/core/Services/<Name>/Controller.php`
2. **Registration** — one line in `db/config/controllers.xml`
3. **Cache clear** — routes are compiled; a new/edited route is invisible until cleared

Skip any one and you get a 404.

## 1. The controller

Real shape (`lib/core/Services/Wiki/Controller.php:8`):

```php
<?php

// (c) Copyright by authors of the Tiki Wiki CMS Groupware Project
//
// All Rights Reserved. See copyright.txt for details and a complete list of authors.
// Licensed under the GNU LESSER GENERAL PUBLIC LICENSE. See license.txt for details.

class Services_Hello_Controller
{
    public function setUp()                    // optional: feature gate, runs before every action
    {
        Services_Exception_Disabled::check('feature_wiki');
    }

    // action_<name>($input); $input is a JitFilter; MUST return an array
    public function action_say($input)
    {
        $name = $input->name->text();          // read+filter each field off JitFilter

        $perms = Perms::get('wiki page', $name);
        if (! $perms->view) {
            throw new Services_Exception_Denied();
        }

        return ['greeting' => tr('Hello %0', $name)];
    }
}
```

**Naming is load-bearing and case-exact:**

- Class **must** be `Services_<Name>_Controller` — `Services_`, not `Service_`
  (`lib/core/Services/Create-a-service` doc; verified `lib/core/Services/Wiki/Controller.php:8`).
- Action method **must** be `action_<name>` — the broker builds
  `'action_' . $action` from the URL (`lib/core/Services/Broker.php:139`).
  Wrong prefix or typo → `Services_Exception` 404 "Action not found"
  (`lib/core/Services/Broker.php:156`).
- Return an **array**. That array is either JSON-encoded or fed to a template
  (see §4). Never `echo`/`print` — return.

`$input` reading (JitFilter, filter-per-access): `$input->page->text()`,
`$input->offset->int()`, `$input->asArray('categIds')`
(`lib/core/Services/Wiki/Controller.php:53-74`). This is the same filtering
model as page bootstrap — see **tiki-input-filtering**. Permission checks inside
the action throw `Services_Exception_Denied` — see **tiki-access-control**.

Optional broker hooks (both auto-detected via `method_exists`,
`lib/core/Services/Broker.php:144-152`):
- `setUp()` — runs before the action; use for `Services_Exception_Disabled::check('feature_x')`.
- `getSection()` returns a string (e.g. `'wiki page'`) → enables banning checks.

## 2. Register in controllers.xml

Add one `<service>` line inside `<services>` (`db/config/controllers.xml:98`):

```xml
<service id="tiki.controller.hello" class="Services_Hello_Controller"/>
```

- `id` = `tiki.controller.<folder-lowercase>`; the URL `controller=` value is that
  trailing lowercase name (`hello`).
- `class` = the exact PHP class name.
- Do NOT edit this file for third-party/extension code — the header says to use
  `_custom/shared/custom.xml` instead (`db/config/controllers.xml:5-8`).

## 3. Clear cache (the #1 gotcha)

Adding OR editing a route requires clearing compiled config, or the endpoint 404s
even though the code is correct:

```bash
find temp/cache/ -type f -not -name index.php -delete
```

## 4. Endpoint + return handling

Endpoint (`tiki-ajax_services.php:33-57`):

```
tiki-ajax_services.php?controller=hello&action=say
```

The broker resolves `Services_Hello_Controller::action_say($input)`, then
(`lib/core/Services/Broker.php:186-193`):

- Looks for template `templates/<controller>/<action>.tpl` (e.g.
  `templates/hello/say.tpl`; real example `templates/comment/post.tpl` for
  `controller=comment&action=post`). If it **exists**, each array key is
  `assign`ed and the template is rendered (wrapped in a modal/ajax layout when
  called via AJAX).
- If the template is **absent**, or the query string contains `&noTemplate`, the
  array is returned as `application/json`. So a pure JSON/REST action just needs
  to return the array and ship no `.tpl`.

Service templates are Smarty and must `|escape` output — see **tiki-smarty-ui**.
User-facing strings via `tr()`/`{tr}` — see **tiki-i18n**.

**Confirm / two-phase pattern.** For state-changing actions, the same action is
hit twice: first render a confirmation form, then perform on POST. The real
mechanism is `Services_Utilities` (`lib/core/Services/Utilities.php`):
`$util->notConfirmPost()` returns the confirm-UI array; on the confirmed POST
`$util->checkCsrf()` validates the ticket, then you act
(`lib/core/Services/Category/Controller.php:206-214`). Returning a `FORWARD`
key makes the broker redirect (`lib/core/Services/Broker.php:175-177`). CSRF
tickets are covered in **tiki-security**.

## 5. Calling from JS

`$.fn.loadService(data, options)` loads a service into an element / modal
(`lib/jquery_tiki/tiki-jquery.js:1663`). Real call
(`templates/tracker_todo/view.tpl:111`):

```js
$(form).parent().loadService({
    controller: 'tracker_todo',
    action: 'view',
    trackerId: 42
}, {});
```

`options` may carry `url`, `modal`, `success`, `load` callbacks. The URL is built
by `$.service(controller, action)` (`lib/jquery_tiki/tiki-jquery.js:1605`).
For a raw fetch, hit the endpoint URL directly and add `&noTemplate` to force JSON.

## Gotchas recap

- `Services_` / `action_` prefixes are **exact and case-sensitive** — a silent 404 otherwise.
- **Cache clear after any route add/edit** — `find temp/cache/ -type f -not -name index.php -delete`.
- Action returns an **array**, never echoes.
- No matching `.tpl` (or `&noTemplate`) ⇒ JSON out; that's the intended REST path.

